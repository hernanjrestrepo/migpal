## Root Cause Analysis

### Original Failure: Simulation 9 (Valentina Morales Cruz)

**Error:** "Failed to extract name from signal"

**Investigation:**
1. The V3.2.0 NameValidator had `MAX_NAME_TOKENS = 2` (maximum 2 words)
2. "Valentina Morales Cruz" has 3 words → rejected as "too_many_words"
3. Additionally, the pattern `'vale'` (Spanish for "ok") was matching inside "Valentina" → false positive

### Root Causes Identified

1. **Too restrictive token limit:** MAX_NAME_TOKENS = 2 is too low for Hispanic names with multiple surnames
2. **Substring pattern matching:** Pattern matching was using substring search, causing false positives (e.g., 'vale' in 'Valentina')
3. **Missing methods:** V3.2.0 NameValidator was missing `has_strong_name_signal()` and `extract_name_from_signal()` methods
4. **Apostrophe rejection:** Names like "O'Brien" were being rejected because apostrophe was in the forbidden symbols list

## Fixes Applied

### 1. Increased Token Limits (name_validator_v32.py)

```python
# Before
MAX_NAME_LENGTH = 20
MAX_NAME_TOKENS = 2
MIN_TOKEN_LENGTH = 2
MAX_TOKEN_LENGTH = 15

# After (V3.2.1)
MAX_NAME_LENGTH = 60
MAX_NAME_TOKENS = 5   # Allows: nombre + segundo nombre + 3 apellidos
MIN_TOKEN_LENGTH = 1  # Allows initials like "J."
MAX_TOKEN_LENGTH = 20
```

### 2. Fixed Pattern Matching (name_validator_v32.py)

Changed from substring matching to word boundary matching for single-word patterns:

```python
# Before
for pattern in NOT_A_NAME_PATTERNS:
    if pattern in cleaned_lower:
        return False, "not_a_name"

# After (V3.2.1)
for pattern in NOT_A_NAME_PATTERNS:
    if ' ' not in pattern and len(pattern) > 1:
        # Use regex word boundary for single words
        if re.search(r'\b' + re.escape(pattern) + r'\b', cleaned_lower):
            return False, "not_a_name"
    else:
        # For multi-word patterns, use substring matching
        if pattern in cleaned_lower:
            return False, "not_a_name"
```

### 3. Added Missing Methods (name_validator_v32.py)

Added `has_strong_name_signal()` and `extract_name_from_signal()` methods to V3.2.0 validator.

### 4. Fixed Character Validation (name_validator_v32.py)

```python
# Before - rejected apostrophes
if re.search(r'[0-9$%@#&*!=+<>/\\|{}\[\]()^~:;"\'`,_]', cleaned):
    return False, "invalid_chars"

# After (V3.2.1) - allows apostrophes, hyphens, periods
if re.search(r'[0-9$%@#&*!=+<>/\\|{}\[\]()^~:;"`_]', cleaned):
    return False, "invalid_chars"
```
